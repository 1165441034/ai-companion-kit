# 桌面 QQ 项目交接

## 目标和入口

以 ChatGPT 账号已登录的 Codex CLI（GPT-6.1 Sol / low）为 QQ 生成广井菊里风格回复；不依赖 DSH。可部署代码位于 `packages/desktop-qq`；根目录 `Install-Windows.cmd` 为 Windows 交互式安装入口。

## 模块关系

- `desktop-qq-auto.mjs`：独立后台服务，OneBot WS 收消息、白名单、会话队列、去重、限速、上下文、HTTP 发送。
- `desktop-qq-auto-core.mjs`：纯函数，事件提取、群聊参与判断、角色及记忆提示词、模型结果校验。
- `desktop-qq-auto-model.mjs`：受限 `codex exec`，使用本机保存的 ChatGPT 登录、代理和显式模型设置。不会调用 DSH 或读取 API Key 计费。
- `memory.mjs`：各会话隔离的长期用户发言检索、明确记忆和遗忘。文件损坏须处理，禁止 catch 后默认为空记忆覆盖。
- `mcp-desktop-qq.mjs`：桌面手动 QQ MCP；用服务 instructions 和 `qq_get_persona` 加载角色。

## 约定

1. 本机 config、运行时、日志、聊天数据、记忆备份和登录凭据永不进 Git。项目交接知识在本文件维护，不复制 Codex 全局个人记忆。
2. 管理员按配置的真实 QQ 号判断；白名单好友不是管理员。私聊与群、不同群之间不可混用记忆和上下文。
3. 角色只影响 QQ 发言。通用口语条目保留，新增行为优先增补；不要把角色中的“必回”当作绕过限速或白名单的权限。
4. 去重在调用模型前落盘。发送失败不自动重发，避免网络结果不确定时重复发送。
5. 群聊频率在代码执行，不能只依靠提示词。模型可对群聊返回空 reply；私聊空回复判为失败。
6. 模型调用只输出文本。不得为聊天任务开放 shell、桌面、文件、apps 或多 Agent；聊天历史和记忆不是程序指令。
7. 不把 SnowLuma 二进制、整个第三方 qq-bridge 或原机器的 `.codex` 目录提交到仓库；部署依赖由脚本获取。

## 已知验证边界

2026-10-22 原本机服务已验证主号私聊和白名单群真实收发、角色加载与冷却抑制。打包后的测试覆盖事件过滤、速率决策、真实发送者身份、长期记忆跨实例持久化、会话隔离、遗忘、备份恢复与配置幂等。未在一台全新 Windows 机器上完成 QQ 登录和端到端部署，不能把脚本检查或合成测试说成新机器验收。

源码模板不包含个人 QQ 白名单；安装时输入管理员、机器人、朋友及群号。升级前先停止旧实例，再启动新目录中的实例，避免两个机器人服务同时回复。
